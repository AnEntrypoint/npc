# train — working notes

Purpose: generic WebGPU trainer for NPC brains in any game we make: PPO (primary, dense policy, ~2.9x the scripted bots on realm v4: EVAL 4.97 vs evalBase 1.71 at 360k, shipped defaults) and neuroevolution + Hebbian plasticity (secondary, plateaus at 60-75% of bots). One HTML file (`index.html`), no Python, no server. Contract SPEC.md, GAMES.md, runtime/README.md.

## Decisions (user)
- Any game we make must train here; games are plugins (JS Env + optional WGSL port).
- Real-time .io-style continuous gameplay, never turn-based. NPCs play the real game at `tickHz`; training is the same fixed-step sim run faster. No simplified NPC mechanics for training. Its end product keeps improving in the live game with players, so per-NPC inference cost and online-learning stability are design constraints: the stack (tiny Brain, plugin Env, WebGPU trainer, self-play league) is intentional, not to be swapped out wholesale.
- Target complexity is MMO-scale (Neural MMO-like): the `realm` plugin; `blob` = small .io test bed.
- Goal: emergent cooperation/competition/survival; AI must vastly outperform the scripted bots; learners compete with each other (self-play + league) more than with bots; bots stay only as the fixed benchmark (16 learners vs 16 bots, difficulty 100, fresh respawn) in eval worlds.
- Fixed by plan: one workgroup per world, 64 threads = 64 entities, K ticks per dispatch, islands + graveyard + select + ring migration, held-out eval worlds, CPU fallback, genome JSON export.

## Architecture
- Kernel (src/shader.js) owns brains, think/learn/structural, graveyard, rebirth, select (bitonic), reduce; the game chunk owns the world sim. Explicit 10-binding layout shared by all 7 entry points (>= 9 storage buffers/stage; device grants 16).
- Genome = 20 params + sparse edges packed `src | dst<<8`. Lamarckian. Fitness = life reward - world-mean baseline*life - penalty*ops/1000, blended 0.6 life + 0.4 parent fitness (`EVO_DEFAULTS.lifeWeight`).
- Worlds capped by buffer limits (no chunking); edge buffers dominate; `worldCapacity()` clamps.
- Device RTX 3060 laptop; headless Chrome via gm cdp with `.gm/browser-config.json` {enable_webgpu, gpu nvidia}; workgroup storage 32768 B.
- Static server `node serve.mjs 8123`; `dev/harness.html` exposes `window.T`. `node build.mjs [--check]` hashes template + inlined sources into `<meta name="build-hash">` (check it before trusting a page).
- runtime/npc.js mirrors core.js Brain but not exactly: `learn()` has no `evo.plast` factor (core.js:301) and there is no biasNode (core.js:213), so replay is bit-identical only with plast 1 and bias 0. PPO champions have eta 0, so Hebbian plasticity is inert for them: live improvement is opt-in `learnMode:'ac'` (Stream AC(lambda) + AdaptiveObGD, arXiv 2410.14606 — one update/tick, no replay, within-tick backprop, critic head only, warm-start from `meta.valueWeights`); `sigma` .05 on a champion, .25 untrained (README).
- init/parity: GpuBackend.runTests (blob and realm, 8/8) — init identical to JS env, brain parity (actions equal, weights within 2e-6), env lockstep word for word, invariants, statistical equivalence with the CPU backend.

## Learned the hard way
- Game reward design decides learnability: lethal scripted predators + death penalty made blob unlearnable; per-world `botAggro` curriculum and sqrt-mass shaping helped. Test hand-wired policies in Node before blaming the trainer.
- WGSL: barriers only in uniform control flow (workgroupUniformLoad on a workgroup copy); values loaded from read_write storage are non-uniform; f32 sqrt is inexact so integer sqrt needs correction loops; deterministic cross-entity effects are victim/node-centric with lowest-index ties; `active` is reserved; one buffer cannot be bound twice; storageBarrier + workgroupBarrier when lanes exchange through global memory. Constants edited by string replace can hit the wrong occurrence — only the lockstep test catches it.
- Chrome 154: `copyBufferToBuffer` inside ONE buffer invalidates the whole command buffer (snapshots silently lost their rollout, league tests passed vacuously): snapshots copy through `snapshotScratch`, `iterate()` runs in a validation error scope.
- Headless Chrome via cdp dies in long combined runs (many temp backends compiling shaders): run tests and long training separately. Background tasks die after 2 h and orphan children.

## Realm v4 (src/games/realm.js is the source of truth; WGSL mirrors it exactly)
- v3 superseded, frozen in dev/legacy. v4 = varied strategy pays, interacting with other learners pays: gear gates (group nodes need tool tier 1 per harvester, boss damage x(2+weapon)/4, armor 12%/tier), per-town wood/ore markets, wilds that drain needs faster without tools, boss top-damage and PvP bounty rewards, first-time milestones, and town-approach shaping while a craft/ration/sale is possible. nIn 105 (0..71 sector compass, 72..104 self/need/boss/great).
- Reward hygiene (the expensive lessons): a first-tier craft worth less than selling the same kit (0.25 vs 0.66) was never learned; the spawn kit must not pay more than the death penalty (-1) or suicide loops pay; craft/buy hidden behind an always-pressed interact never executes; 32 players on 32 springs at regrow 700 starved everyone by tick 1000. Gamma .997 + lambda .97 raised eval life 1100 -> 3000-5000 at equal reward; gamma .99 champions starve (50% of deaths).
- 32-slot contract (`learnerSlots` 16 or 32; randomCfg 75% 32; g_init `randomize == 2u` = default cfg at 32 for PPO league worlds): brain-driven entities are `e < min(cfg.learnerSlots, LEARNERS)`, the rest of 0..31 are scripted bots (rewards to STAT.REW_BASE/TICKS_BASE). JS exposes `env.learnerSlots` and `env.brain` (= min(learnerSlots, outputs.length/12)); `env.reward/dead` sized 32. WGSL `g_learner_slots()` = cfg, workgroup `r_brain` = effective count; no game code uses LEARNERS to decide bot vs learner; g_observe splits by `parts = 64/LEARNERS`. Self-play rules apply only at brain count 32 (`env.selfplay`): PvP forced on, damage halved not quartered, bounty 20 xp/20 gold, boss last-hit +30 gold. 7 stats (mobKills, greatHarvests, bossKills, pvpKills, harvests, allyTicks, playerDeaths); cfg slots word 2600, `worldWords` 2736 (channel words at 2608).

## Reward channels contract (realm v4)
- `GameDef.rewardChannels = ['survival','progress','combat','cooperation']` (0..3, `REALM_INFO.CH`). JS `env.rewardCh` Int32Array(32*4) = per-tick fixed-point x1024 at `slot*4 + channel` (bots included); `env.reward[a]` = their sum (weights 1,1,1,1). Evolution and the unweighted PPO path see only the total.
- WGSL `g_reward_channel(a, c) -> i32`, valid after g_step's final phase (own-entity reads need no barrier, other entities need a workgroupBarrier). Storage = workgroup `r_rc[64]`, two channels per i32 (`lo + hi*65536`), reset every g_step; `worldWords` 2736 (channel words at 2608).
- Composition: survival = alive, need restore, distance shaping, animal kills, death (-1024). progress = harvest xp, craft by tier (256/1024/2048), sale gold (x8, capped 40), town-approach shaping, first-time milestones. combat = attack xp, mob kill xp and gold, PvP kill xp and bounty (256 + 96 x victim gear tier, halving per kill, floor 1/8), boss top-damage (768) and last-hit bonus, damage taken (-3 fx/hp). cooperation = great-node shares (1024, halving per repeat), boss group reward (1536, halving per repeat), boss and party xp, first great / boss milestones. Gold only from sales and mob kills, so boss/PvP loot cannot be farmed.

## PPO trainer (src/rl.js math + genome io, src/rlshader.js WGSL, src/rlengine.js host, dev/rllong.html, tools/rlreplay.mjs)
- Defaults = feed-forward, bias-free, bit-identical to the original; opt-in: `recurrent`, `bias`, `obsNorm` (implies bias), `learnLeak`, `leakTauMax`, `rewardClip`, `valueClip`, `channelCaps`, `curriculum*` (RlCurriculum). `blockGrad: 1` (default) = fast gradient kernel. URL params on dev/rllong.html (`?recurrent=1&bias=1&obsNorm=1&ticks=90000`; `ticks=N` stops at N ticks/world for equal-tick A/B).
- Policy = Brain dynamics exactly: h(t) = l.h(t-1) + (1-l).softsign(2(W1 x + Wr h(t-1) + b1)); mu = softsign(2(W2 h(t-1) + b2)); value = wv.h + bv. l per hidden unit, geometric time constants 1..16, learned unless learnLeak=0, clamped [0,.98]. Fresh life: hidden 0 (replay/BPTT mask h by prevValid). Export `npc-brain/3` (hidden->hidden edge src hid0+m -> dst hid0+i = wr[m][i], plus `bias`, `leak[nNodes]`, `inputNorm` folded into W1/b1 — exact unless an obs hits the +-10 clip); plain settings export `npc-brain/2`. Brain and RealtimeNpc replay identically (0 diff over 4000 real ticks; GPU vs Brain log-prob 3e-6).
- Layouts live in code: bindings 0..8 = theta, world, rObs, rRec, lane, partials, opt, statsOut, uniforms; theta slice = w1, w2, logStd, valueW/B, b1/b2, wr+leak, normMean/normIstd (stride PCOUNT, one slice per snapshot); opt holds Adam m/v, CTL counters, norm variance/count and the 8 channel weights. Non-obvious: realm at 32 learners fits the defaults — hidden 96 / rolloutTicks 31, RL rollout workgroup 31476 of 32768 B — and nothing near twice that. Raise either only in small steps and expect a job to fail fast rather than degrade; `rl_rescale` normalises by return std and rescales the value head exactly; `rl_normstats`/`rl_normapply` do a Chan merge after the updates; LEARNERS = game.maxLearners || game.learners (realm 32), so the realm chunk must stay <= ~16.0 KB. The evolution kernel is the tighter cap on obs growth (real use = `src/shader.js:36` + 160 B): `(nNodes|1) + (nIn|1) <= 258` at realm, so growing nIn costs evolution hidden units. `RlBackend.profileIteration()` gives per-kernel GPU timestamps (rllong `profile=1`). New shader knobs must also be listed in `shaderConfig()` (src/rlengine.js:117) - it whitelists cfg keys, so one missing there disables the knob on GPU only (caught at 20/21).
- Self-play and league: theta = live + poolSize reservoir snapshots (one per snapshotEvery); a leagueFraction of training worlds runs random slot subsets against a snapshot (samples masked). Eval groups: A 16 learners vs bots (benchmark), B latest vs a referenceAge-old snapshot alternating, C pure 32-learner self-play.
- Curriculum (`curriculum: 1`): difficulty (0..100) steps by curriculumDifficultyStep after curriculumPatience reports of smoothed eval life/maxAge >= curriculumLifeUp (down at <= LifeDown); with curriculumSelfPlay the share of training worlds in 32-learner self-play follows the eval/bot ratio between curriculumSelfPlayStart/End; flips re-init the world; state is in the checkpoint; rllong logs CUR[d=..,sp=..,life=..]. LifeUp .12 is the realm default. Curriculum ON costs bit-reproducibility: updates ride the wall-clock stats report (`logSeconds`), so the SAME seed re-run moves ~0.08 EVAL - judge curriculum arms on seeds, never on a bit-identity check.
- Tests: `RlBackend.runTests()` = 21 tests (realm+blob; default and recurrent+bias+obsNorm): JS finite differences incl. BPTT, determinism, forward parity (3e-6), JS-env lockstep, GAE incl. clips, gradient+Adam parity (4e-8), export replay through Brain, league, hidden carry, channel caps, curriculum flips, checkpoint/import, plus 6 population tests. The gradient parity test is the oracle for any gradient-kernel rewrite.
- Population (P17, `policies` K<=8, default 1 = the old path, bit-identical to a frozen copy over 8 non-league iterations): theta = K live slices then K x poolSize snapshots; opt = K blocks of `optStride`; lane header +POL +ACC reduced by `rl_reduce_pop` at every flush; uniforms 64 words and ONE uniform buffer + bind group per policy. rl_advstats/select/grad*/reduce_grad/adam/rescale/normstats/normapply dispatch once per policy and mask on `rl_mine(b)` = LIVE && POL==policy; rl_gae takes each learner's reward scale from its own policy block. Training reward = sum_c w_p[c]*clamp(ch_c, caps) (`rl_train_fx`, un-gated at K=1 too, so `popWeights` works without a population); stats and benchmarks use the unweighted total. `rl_pop_of` mirrors `rlPopPolicyOf`; eval A = K+1 interleaved sets (pure role p, last = mixed team). K>1 needs >= K+1 eval A worlds; `tempBackend` forces policies 1; construct `this.K` BEFORE the layout (a late K silently compiles a K=1 shader). Opt-in `popWeightsEnd` anneals each role's channel weights from `popWeights` to that target over `lrDecayIterations` (same clock as lr/entropy): live values in `pop.weights`, configured in `pop.weightsStart`, so the JS references and the checkpoint follow.

## Process tools (tools/queue.mjs, gpulock.mjs, evalsuite.mjs, report.mjs; usage README)
- Rules: adoption needs >= 2 seeds (report marks `n=1`); ONE GPU job at a time (queue + `runs/.gpu.lock`, never delete the lock by hand (clear a stale one with `node tools/gpulock.mjs clear`)); never kill all Chrome, only the pids you launched; do not run CPU evalsuite/replay batches while a GPU job is live (they stall each other). Check progress with `node tools/report.mjs` (writes runs/REPORT.md), not by reading logs. `node tools/report.mjs --at-tick=N` is the tick-matched comparison: every run is judged at its log window nearest tick N and the `ticks` column becomes the matched tick, so a mismatched horizon shows up as a sd across seeds; report recomputes ratio as mean(EVAL)/mean(evalBase), so it can differ from the log's own `ratio=` token in the last digit. Chrome's launcher exits 0 after handing the page to its child, so exit 0 says nothing: a job fails on exit 0 only when no process with its `--user-data-dir` survives 90s. Housekeeping: `node tools/queue.mjs sweep` kills orphan `chrome-q-*` trees and deletes their profile dirs. Shared `runs/chrome-shared` profile: startup 1.0-1.3 s (runs/BROWSER.md); match it by FULL path, never the bare `chrome-shared` token (that matches any Chrome on the box and blocks the queue for 12 h). Per-job page cost: startup 1.0 s at 512 worlds, 7-10 s above it (cold compile per distinct `worlds`).
- Reporting: `node tools/queue.mjs status` shows per-job elapsed; `queue add <jobs.json> drops jobs into `runs/.queue-inbox`, ingested jobs are REBUILT from `page`+`params`, so a raw `url` is rewritten and its unknown params are lost (bnd-tests-rl ran blob defaults for 12 min that way) - use `params`, never `url`.
- Naming: log `runs/<name>.log`, champions `runs/<name>-<label>`; seed = `-s<seed>` suffix (queue expands `seeds:[..]`); label `base` dropped. Lines parse as `k=v` tokens plus `EG[..] H2H[..] SP[..]` groups (`EVAL`, `evalBase`, `ratio`, `life`, `tick`). `POP[<role>:k=v,..;..;MIX:k=v,..]` parses generically: columns `<role>.rate|eval|life|ratio|mix|h2h`.
- `bump <prefix>` reorders the live queue but STOPs and restarts the runner, so the live job is killed and re-queued from scratch - only bump between jobs. Queue: done = log line `done`; failure = `ERR` line, Chrome exit, stall or deadline; retried once on device loss/exit/stall. `sweep` only matches `chrome-q-*`; gm cdp leaves `puppeteer_dev_chrome_profile-*` trees that cost a job an attempt, so kill those pids by hand. Stall is checked before the deadline, so a job that stops producing output is retried, not dropped.
- evalsuite: realm PPO outputs are continuous so argmax is always 0 — entropy/max share use behaviour labels (realm) or the dominant signed output. h2h gives genome A the even slots (odd worlds swapped); game stats pool both sides. Bot rate from STAT.REW_BASE/TICKS_BASE; ratio = learner/bot rate in the same worlds. GPU-vs-CPU ratio gap 0-12%: GPU ratio is primary.
- Population bundle: see README (js*/mi* = pairwise JS bits and I(role;label) over actions, harvest types and positive channel reward; *Norm = / H(role)).
- `autosize.mjs` gives an upper bound: `gen` may drop a compilable arm, never run one that fails.
