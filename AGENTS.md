# train — working notes

Purpose: generic WebGPU trainer for NPC brains (PPO primary; neuroevolution + Hebbian plasticity secondary, plateaus at 60-75% of bots). One HTML file (`index.html`), no Python, no server. Contract: SPEC.md, GAMES.md, runtime/README.md. v4 shipped at ~2.9x the bots (4.97 vs 1.71 @360k); current numbers: the v5 section and AB-ARCHIVE.md.

## Decisions (user)
- Any game we make must train here; games are plugins (JS Env + optional WGSL port).
- Real-time .io-style continuous gameplay, never turn-based. NPCs play the real game at `tickHz`; training is the same fixed-step sim run faster. No simplified NPC mechanics for training; the end product keeps improving live with players, so per-NPC inference cost and online-learning stability are constraints: the stack (tiny Brain, plugin Env, WebGPU trainer, self-play league) is intentional.
- Target complexity is MMO-scale (Neural MMO-like): the `realm` plugin; `blob` = small .io test bed.
- Goal: emergent cooperation/competition/survival; AI must vastly outperform the scripted bots; learners compete with each other (self-play + league) more than with bots; bots stay only as the fixed benchmark (16 learners vs 16 bots, difficulty 100, fresh respawn) in eval worlds.
- Fixed by plan: one workgroup per world, 64 threads = 64 entities, K ticks per dispatch, islands + graveyard + select + ring migration, held-out eval worlds, CPU fallback, genome JSON export.

## Architecture
- Kernel (src/shader.js) owns brains, think/learn/structural, graveyard, rebirth, select (bitonic), reduce; the game chunk owns the world sim. Explicit 10-binding layout shared by all 7 entry points (>= 9 storage buffers/stage; device grants 16).
- Genome = 20 params + sparse edges packed `src | dst<<8`. Lamarckian. Fitness = life reward - world-mean baseline*life - penalty*ops/1000, blended 0.6 life + 0.4 parent fitness (`EVO_DEFAULTS.lifeWeight`).
- World buffer = `WORLD_HDR_WORDS` 28 header words (stats at word 8, `NSTATS` 20) + `worldWords`. `STAT.GAME0` 9 leaves 11 game slots; realm uses 10. Both shaders template `STATS_OFF`/`NSTATS`/`GAME_OFF` from core.js - never hardcode 16 or 24 again. WGSL stat indices are generated from `STAT` (`STAT_CONSTS`) and the league role slots are `NSTATS + 0/2`: a literal `select(18u, 16u, ...)` survived the 16->20 growth and zeroed every h2h tick (10/21 tests) instead of crashing.
- Worlds capped by buffer limits (no chunking); edge buffers dominate; `worldCapacity()` clamps.
- Device RTX 3060 laptop; headless Chrome via gm cdp (`.gm/browser-config.json` {enable_webgpu, gpu nvidia}); workgroup storage 32768 B.
- Static server `node serve.mjs 8123`; `dev/harness.html` exposes `window.T`. `node build.mjs [--check]` hashes template + inlined sources into `<meta name="build-hash">` (check it before trusting a page).
- runtime/npc.js mirrors core.js Brain but not exactly: `learn()` has no `evo.plast` factor (core.js:301) and there is no biasNode (core.js:213), so replay is bit-identical only with plast 1 and bias 0. PPO champions have eta 0, so Hebbian plasticity is inert for them: live improvement is opt-in `learnMode:'ac'` (Stream AC(lambda) + AdaptiveObGD - one update/tick, critic head only, warm-start from `meta.valueWeights`); `sigma` .05 on a champion, .25 untrained (README).
- init/parity: GpuBackend.runTests (blob, realm, 8/8) - init identical to JS env, brain parity (weights within 2e-6), env lockstep word for word, invariants, CPU-backend equivalence.

## Learned the hard way
- Game reward design decides learnability: lethal scripted predators + death penalty made blob unlearnable; per-world `botAggro` curriculum and sqrt-mass shaping helped. Test hand-wired policies in Node before blaming the trainer.
- WGSL: barriers only in uniform control flow (workgroupUniformLoad on a workgroup copy); values loaded from read_write storage are non-uniform; f32 sqrt is inexact so integer sqrt needs correction loops; deterministic cross-entity effects are victim/node-centric with lowest-index ties; `active` is reserved; one buffer cannot be bound twice; storageBarrier + workgroupBarrier when lanes exchange through global memory. Constants edited by string replace can hit the wrong occurrence — only the lockstep test catches it; a field the GPU sets at init but JS sets inside `step()` diverges only at tick 0 (`env.brain`).
- Chrome 154: `copyBufferToBuffer` inside ONE buffer invalidates the whole command buffer (snapshots silently lost their rollout, league tests passed vacuously): snapshots copy through `snapshotScratch`, `iterate()` runs in a validation error scope.
- Headless Chrome via cdp dies in long combined runs (many temp backends compiling shaders): run tests and long training separately.

## Reward channels contract (realm v4)
- `GameDef.rewardChannels = ['survival','progress','combat','cooperation']` (0..3, `REALM_INFO.CH`). JS `env.rewardCh` Int32Array(32*4) = per-tick fixed-point x1024 at `slot*4 + channel` (bots included); `env.reward[a]` = their sum (weights 1,1,1,1). Evolution and the unweighted PPO path see only the total.
- WGSL `g_reward_channel(a, c) -> i32`, valid after g_step's final phase (own-entity reads need no barrier, other entities need a workgroupBarrier). Storage = workgroup `r_rc[64]`, two channels per i32 (`lo + hi*65536`), reset every g_step; `worldWords` 2736 (channel words at 2608).
- Composition: survival = alive, need restore, distance shaping, animal kills, death (-1024). progress = harvest xp, craft by tier (256/1024/2048), sale gold (x8, capped 40), town-approach shaping, first-time milestones. combat = attack xp, mob kill xp and gold, PvP kill xp and bounty (256 + 96 x victim gear tier, halving per kill, floor 1/8), boss top-damage (768) and last-hit bonus, damage taken (-3 fx/hp). cooperation = great-node shares (1024, halving per repeat), boss group reward (1536, halving per repeat), boss and party xp, first great / boss milestones. Gold only from sales and mob kills, so boss/PvP loot cannot be farmed.

## PPO trainer (src/rl.js math + genome io, src/rlshader.js WGSL, src/rlengine.js host, dev/rllong.html, tools/rlreplay.mjs)
- Defaults = feed-forward, bias-free, bit-identical to the original; opt-in: `recurrent`, `bias`, `obsNorm` (implies bias), `learnLeak`, `leakTauMax`, `rewardClip`, `valueClip`, `channelCaps`, `curriculum*` (RlCurriculum). `blockGrad: 1` (default) = fast gradient kernel. URL params on dev/rllong.html (`?recurrent=1&bias=1&obsNorm=1&ticks=90000`; `ticks=N` stops at N ticks/world for equal-tick A/B).
- Policy = Brain dynamics exactly: h(t) = l.h(t-1) + (1-l).softsign(2(W1 x + Wr h(t-1) + b1)); mu = softsign(2(W2 h(t-1) + b2)); value = wv.h + bv. l per hidden unit, geometric time constants 1..16, learned unless learnLeak=0, clamped [0,.98]. Fresh life: hidden 0 (replay/BPTT mask h by prevValid). Export `npc-brain/3` (hidden->hidden edge src hid0+m -> dst hid0+i = wr[m][i], plus `bias`, `leak[nNodes]`, `inputNorm` folded into W1/b1 — exact unless an obs hits the +-10 clip); plain settings export `npc-brain/2`. RealtimeNpc replays identically (0 diff over 4000 ticks; GPU vs Brain log-prob 3e-6).
- Layouts live in code: bindings 0..8 = theta, world, rObs, rRec, lane, partials, opt, statsOut, uniforms; theta slice = w1, w2, logStd, valueW/B, b1/b2, wr+leak, normMean/normIstd (stride PCOUNT, one slice per snapshot); opt holds Adam m/v, CTL counters, norm variance/count and the 8 channel weights. Non-obvious: realm at 32 learners fits the defaults - hidden 64 / rolloutTicks 31, RL rollout workgroup 31380 of 32768 B; raise either only in small steps and expect a job to fail fast rather than degrade. `rl_rescale` normalises by return std and rescales the value head; `rl_normstats`/`rl_normapply` do a Chan merge; LEARNERS = game.maxLearners || game.learners (realm 32), so the realm chunk must stay <= ~16.0 KB. The evolution kernel is the tighter cap on obs growth (real use = `src/shader.js:36` + 160 B): `(nNodes|1) + (nIn|1) <= 260` at realm, so growing nIn costs evolution hidden units. `RlBackend.profileIteration()` gives per-kernel GPU timestamps (rllong `profile=1`). New shader knobs must also be listed in `shaderConfig()` (src/rlengine.js:117) - it whitelists cfg keys, so one missing there disables the knob on GPU only (caught at 20/21).
- Self-play and league: theta = live + poolSize reservoir snapshots (one per snapshotEvery); a leagueFraction of training worlds runs random slot subsets against a snapshot (samples masked). Eval groups: A 16 learners vs bots (benchmark), B latest vs a referenceAge-old snapshot alternating, C pure 32-learner self-play.
- Curriculum (`curriculum: 1`): difficulty (0..100) steps by curriculumDifficultyStep after curriculumPatience reports of smoothed eval life/maxAge >= curriculumLifeUp (down at <= LifeDown); with curriculumSelfPlay the share of training worlds in 32-learner self-play follows the eval/bot ratio between curriculumSelfPlayStart/End; flips re-init the world; state is in the checkpoint; rllong logs CUR[d=..,sp=..,life=..]. LifeUp .12 is the realm default. Curriculum ON costs bit-reproducibility: updates ride the wall-clock stats report (`logSeconds`), so the SAME seed re-run moves ~0.08 EVAL - judge curriculum arms on seeds, never on a bit-identity check.
- Tests: `RlBackend.runTests()` = 21 tests (realm+blob, default + recurrent/bias/obsNorm): JS finite differences incl. BPTT, determinism, forward parity (3e-6), JS-env lockstep, GAE incl. clips, gradient+Adam parity (4e-8), export replay through Brain, league, hidden carry, channel caps, curriculum flips, checkpoint/import, plus 6 population tests.
- Telemetry: `fit=1` = `FIT[ev,adv,sig,std,sat,dead]`; audit runs/telemetry-audit.md.
- Population (P17, `policies` K<=8, default 1 = the old path, bit-identical to a frozen copy over 8 non-league iterations): theta = K live slices then K x poolSize snapshots; opt = K blocks of `optStride`; ONE uniform buffer + bind group per policy. rl_advstats/select/grad*/reduce_grad/adam/rescale/normstats/normapply dispatch once per policy, masked on `rl_mine(b)` = LIVE && POL==policy; rl_gae reads the reward scale from the learner's own policy block. Training reward = sum_c w_p[c]*clamp(ch_c, caps) (`rl_train_fx`, un-gated at K=1 too, so `popWeights` works without a population); stats/benchmarks use the unweighted total. eval A = K+1 interleaved sets (pure role p, last = mixed team); K>1 needs >= K+1 eval A worlds; `tempBackend` forces 1; construct `this.K` BEFORE the layout (a late K silently compiles a K=1 shader). `popWeightsEnd` anneals each role's weights to a target over `lrDecayIterations`.

## Process tools (tools/queue.mjs, gpulock.mjs, evalsuite.mjs, report.mjs; usage README)
- Rules: adoption needs >= 2 seeds (report marks `n=1`); ONE GPU job at a time (queue + `runs/.gpu.lock`, never cleared by hand - use `node tools/gpulock.mjs clear`); never kill all Chrome, only the pids you launched; do not run CPU evalsuite/replay batches while a GPU job is live (they stall each other). Check progress with `node tools/report.mjs` (writes runs/REPORT.md), not by reading logs.
- Port trap: a wrong port 404s instantly and the job sits `pending`; start our own (`node serve.mjs 8124`) and pass `--port=8124`. The URL is baked at INGEST (queue.mjs:191), so a bad-port job keeps it through `resume` - re-ingest with `--replace`. `node tools/report.mjs --at-tick=N` judges every run at its log window nearest tick N, so a mismatched horizon shows up as a sd across seeds. Chrome's launcher exits 0 after handing the page to its child: a job fails on exit 0 only when no process with its `--user-data-dir` survives 90s. Housekeeping: `node tools/queue.mjs sweep` kills orphan `chrome-q-*` trees and deletes their profile dirs. Shared `runs/chrome-shared` profile: startup 1.0-1.3 s; match it by FULL path, never the bare `chrome-shared` token (that matches any Chrome on the box and blocks the queue for 12 h).
- Wall clock per decision: `--paired=<run>` prints arm-baseline deltas on the SAME seed; the delta sd is the noise on the DECISION, 3-17x tighter than arm means. Horizon beats length: paired-delta sd 0.60 @150k vs 0.35 @200k, so a 150k screen is FALSE ECONOMY; judge at ~200k. `--at-tick` interpolates between log windows.
- CPU contention, not config: low GPU util with low wt/s = host starved; check nvidia-smi before blaming config. Never read throughput off a `profile=1` arm (timestamp queries serialize dispatches: 22-87k vs 259-372k live). Wall wt/s is VOID under contention; GPU timestamps stay valid (~1.5% spread, min of 3).
