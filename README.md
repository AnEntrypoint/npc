# train

Trains plastic, self-pruning NPC brains for any real-time game on your own GPU. One HTML file, WebGPU, no Python, no server for training.

## Run
- `node build.mjs` writes the single-file `index.html` (open it directly in Chrome/Edge; WebGPU 113+, Safari 26, Firefox 141+). Without WebGPU it falls back to the CPU backend. The build stamps the artifact with `<meta name="build-hash">`, a hash of the template plus all inlined sources, so `node build.mjs --check` proves the file you are testing was built from the sources you actually have (exit 1 and "is stale" otherwise) — a file copied or rebuilt elsewhere cannot look current.
- `node serve.mjs 8123` serves the folder for development (`/dev/harness.html` exposes the engine, `/dev/longrun.html?game=realm&worlds=2048&islands=32&minutes=40&name=run1` trains headlessly and posts its log and champions to `runs/`).
- Pick a game, press Start. Curves compare the evolved reward rate with the scripted-bot baseline, in training worlds and in held-out eval worlds. Watch mode plays the champions in the real game at its real-time tick rate. Export champions as `npc-brain/2` JSON.

## Trainers
- Evolution (default): sparse plastic graphs, islands, archive, graveyard (see SPEC.md).
- PPO (Trainer = PPO in the UI, `RlBackend` in `src/rlengine.js`): GPU policy gradient on the same simulations. It trains a dense two-layer network that is exactly the deployed Brain dynamics (input -> hidden with softsign(2 x), hidden(t-1) -> output) with Gaussian exploration noise, GAE, PPO-clip and Adam, all in WGSL, and exports a normal dense `npc-brain/2` genome (`nIn + nOut + hidden` nodes, no plasticity or pruning) that `core.js` `Brain` and `runtime/npc.js` run unchanged. Games with `maxLearners` (realm: 32 learner slots, pure self-play worlds) train with a league: a pool of frozen past snapshots plays inside a share of the training worlds (their samples are masked), and `readStats().league` reports latest-vs-older head-to-head reward, pure self-play stats and the pool, next to the 16-learners-vs-bots benchmark eval. On realm the training worlds run that benchmark composition themselves (16 learners vs 16 bots, no domain randomization): +13% eval reward/tick and +40% throughput at 3 seeds and 300k ticks, while league and self-play worlds stay opt-in. Optional memory and hygiene (all off by default, see SPEC.md): `recurrent=1` trains a leaky Elman policy with truncated BPTT that exports as an ordinary `npc-brain/3` graph (hidden-to-hidden edges plus a per-node `leak` vector), `bias=1` adds bias nodes, `obsNorm=1` keeps running observation statistics and folds them into the first layer at export, `rewardClip`/`valueClip`/`channelCaps` stabilise the return scale, `curriculum=1` raises difficulty and the self-play share automatically - measured at 5 seeds on realm (difficulty pinned at 100, the self-play share ramping 0.15 -> 0.5 with the eval/bot ratio) it gives +0.07 eval reward/tick against the bots (t=1.2) and +0.20 in pure self-play (t=2.7), but its updates ride the wall-clock stats report, so it costs run-to-run reproducibility worth ~0.08 on the benchmark, and it stays off by default. Population training (`policies=3` or `4`, off by default: measured at equal ticks on realm with 2 seeds, a population of 3-4 is 10-20% below a single generalist when the training worlds keep the scripted bots and only ties it in pure self-play, so `policies=1` stays the default): several policies with their own network, Adam state, normalisation, league snapshots and a reward weight vector over the game's reward channels (realm presets: generalist 1/1/1/1, hunter 0.5/0.5/2/0.5, crafter 0.5/2/0.5/1, forager 2/1/0.3/2 for survival/progress/combat/cooperation) share every world, so they compete, specialise and trade; `popMix` chooses balanced (every role in every world), random per slot or archetype worlds, `popRoles`/`popWeights`/`popFractions` edit roles (URL form `popWeights=1,1,1,1/0.5,0.5,2,0.5/...`), the benchmark worlds are split into one pure world set per role plus a mixed team, and the UI has a population editor and per-role curves and table. Exports are a JSON array of `{format: 'npc-population-member/1', index, role, weights, channels, fraction, genome}` members that `tools/evalsuite.mjs`, `tools/replay.mjs` and `runtime/server.mjs` load; the roles do specialise (a crafter that harvests and sells, a hunter that roams and fights), just not into a better team than one generalist. Typical use: hidden 96 (realm ships 64 per game: equal eval reward at 3 seeds and 300k ticks, ~25% less training compute and a third off live per-NPC inference), 512-2048 worlds, epochs 1, minibatches 4, lr 1e-3, entropy bonus .02 annealed to .002 over the first 2000 iterations (+9% then +2.6% realm eval reward at 3 seeds; .03 is worse, so .02 is the plateau; blob is pinned back to .001 flat per game, where higher entropy earns nothing). `Run tests` proves rollout determinism, forward/GAE/gradient/Adam parity with `src/rl.js` and export replay through `Brain`.

## Games
- `realm` (v4): MMO-style continuous world (biomes, resource nodes, food/water meters, gather/craft/sell economy at towns with separately saturating wood and ore prices, three combat styles with a style triangle, mobs, animals, PvP with bounties, day/night, scarce springs and berries, a wilds zone that drains food and water unless you carry a tool tier, crafted gear tiers that gate group harvest nodes and boss damage, roaming style-resistant bosses with a top-damage and last-hit bonus, party mechanics). 64 entities per world, 16 learners in evolution, 32 learner slots in PPO self-play, four reward channels (survival, progress, combat, cooperation) exposed to the trainer.
- `blob`: `.io`-style continuous arena (agar-like), small test bed. PPO here prefers `rolloutTicks=16&gamma=0.999` (eval reward/tick 0.59 vs 0.52 at equal ticks, 3 seeds), which are now blob's built-in defaults through `RL_GAME_DEFAULTS` in `src/rl.js` — an explicit URL param still overrides them; neither transfers to realm, so realm keeps the defaults.
- New game: see GAMES.md. A game is a JS `Env` (the real game logic) plus a WGSL port; `GpuBackend.runTests()` proves the port is a lockstep mirror.

## Tools
- `dev/longrun.html` headless training page (params: game, worlds, islands, mutation, lifeWeight, penaltyEnd, ramp, maxEdges, minutes, name, seed, logSeconds, difficultyStart/End, difficultyRamp). Launch in a standalone Chrome: `chrome --headless=new --user-data-dir=<dir> --enable-unsafe-webgpu "http://localhost:8123/dev/longrun.html?game=realm&worlds=1024&islands=16&maxEdges=96&penaltyEnd=0.1&minutes=120&name=run1"`; progress lines go to `runs/run1.log`, champions to `runs/run1`.
- `dev/ab.html` interleaved A/B page (several backends in one page; `variants=label:key=val,key=val;...`, `game=realm2|realm3a|realm31|realm33` selects a frozen older rule set from `dev/legacy/`, `tests=1` runs GpuBackend.runTests, champions saved to `runs/<name>-<label>` every `saveEvery` log windows). Logs go to `runs/<name>.log` through `node serve.mjs 8123`.
- `dev/rllong.html` headless PPO page (params: game, worlds, minutes, name, logSeconds, saveSeconds, any RL option such as hidden, rolloutTicks, lr, lrEnd, entropy, epochs, minibatches, gamma, lambda, plus `variants=label:key=val,key=val;...` to interleave several trainers at equal GPU time; `tests=1` runs `RlBackend.runTests`, `bench=1` the throughput benchmark, `profile=1` per-kernel timings including GPU timestamp queries, `ticks=N` stops at N ticks per world so runs compare at equal ticks, `recurrent=1&bias=1&obsNorm=1`, the curriculum options and the population options `policies`, `popMix`, `popPure`, `popPeriod`, `popRoles`, `popWeights`, `popFractions`; population runs log a `POP[...]` group per progress line and save the bundle to `runs/<name>-<label>` plus one genome per role as `-<label>-<role>`). Launch: `chrome --headless=new --user-data-dir=<dir> --enable-unsafe-webgpu --no-first-run --no-sandbox "http://localhost:8123/dev/rllong.html?game=realm&worlds=1024&minutes=30&name=ppo1"`; progress goes to `runs/ppo1.log`, the champion genome to `runs/ppo1-base` (and the best-eval snapshot to `runs/ppo1-base-best`).
- `tools/rlreplay.mjs [--game=realm] [--worlds=32] [--periods=2] [--teacher] runs/<genome>` replays a dense genome through `core.js` `Brain` in Node with the fair-start eval protocol of the GPU eval worlds (difficulty 100, everyone respawned fresh each `maxAge`) and prints learner reward/tick, scripted baseline, mean life; `--teacher` drives the learner slots with the game's scripted teacher (the pure-bot reference).
- `tools/replay.mjs [--game=../dev/legacy/realm2.js] [--ticks=6000] [--worlds=4] [--top=4] runs/<champions> [random]` replays saved champions in Node against the scripted bots and prints per-life behaviour (action shares, entropy, distance, safe-zone, wilds and ally time, harvests by type, causes of death, levels, gear tiers, crafts, ration buys, boss and PvP kills); `--selfplay` drives all 32 slots with the champion.
- `tools/acab.mjs [--game blob] [--champ runs/<name>-base | --random] [--modes frozen,heb,ac] [--ac sigma=0.05] [--ticks 50000] [--windows 5] [--seeds 11,12]` measures online learning in the JS env on the CPU: frozen vs Hebbian vs streaming AC (`learnMode:'ac'`), printing per-window reward/tick/learner x1e3, mass gain, deaths per learner, weight drift and mean |delta|. `--champ` replays a trained genome, `--random` builds an untrained one. See runtime/README.md for the measured sigma rule.
- `tools/clone.mjs --game realm` (experimental) distils a game's scripted teacher into a sparse genome (see AGENTS.md for results).
- `tools/prune.mjs --genome=<dense PPO genome> [--game=realm] [--targets=2048,1024,512,256] [--methods=fisher+rewire,fisher,mag,structured] [--out=<dir>]` turns a dense feed-forward or recurrent PPO champion into sparse `npc-brain/3` genomes by iterative pruning with distillation (Node worker threads, CPU only, about 25 min for six targets of the 11,232-edge realm champion). It records on-policy chunks of the teacher's deterministic outputs in realm bot worlds, 32-learner self-play and randomised cfgs (difficulty 100/60/40), fine-tunes a masked student that is the exact Brain math (softsign, bias, per-node leak; recurrent genomes by truncated BPTT) with Adam on MSE + movement-difference + threshold-hinge loss, and after every pruning round drops hidden units that no longer connect input to output and renumbers nodes. Methods (`<saliency>[/layer][+rewire][+dagger]`): `mag` |w|, `act` |w| x rms(source activation), `fisher` mean squared (w x gradient) over minibatches, `structured` whole hidden units, `hybrid` units then `act`; `+rewire` RigL-style drop/grow rounds at each target; `+dagger` student rollouts relabelled by the teacher (`--dagger=1`). Every snapshot is exported next to the input as `<genome>-<method>-s<target>` (plus `.eval.json`), measured for `Brain.step` time, checked in lockstep against `RealtimeNpc` and the student math (`verify`), and scored with `tools/evalsuite.mjs` (bots, head-to-head vs the teacher, self-play; `--evalSeeds=6 --evalWorlds=4`); the report is `<genome>.prune.md/json` (`--report=<name>` renames it) and lists the smallest snapshot reaching 95/90/80% of the teacher's bots reward. Useful flags: `--jobs`, `--samples` (recorded ticks, default 450000), `--steps`/`--finalSteps`/`--ratio` (fine-tune budget per round / per target / edge fraction kept per round), `--cache=<file>` (reuse recorded data), `--skipEval`, `--suites`, `--compareSuites` (suites for every method after the first). `tools/prune.mjs --plasticity=1 --genome=<sparse genome> [--apply=1]` sweeps online Hebbian plasticity (eta, A, B, C, D, decay) and the prune/grow step (pruneT, growP, growW) against the same genome with them off (paired seeds, verdict helps/neutral/hurts, Brain vs RealtimeNpc lockstep under plasticity), and `--apply` stores the result in `meta.recommended` with `meta.maxEdges` (growth headroom; `evalsuite` and `RealtimeNpc` honour it). Library code: `src/prune.js` (not part of the browser build).

## Process tools (replicates, fixed evaluation, GPU queue, report)
- Rule: any adoption decision needs at least two seeds; `dev/rllong.html` and `dev/longrun.html` accept `?seed=N` (default unchanged) and every log line carries `seed=`; `report` shows `n=1` on single-seed groups.
- `tools/queue.mjs` serialises GPU jobs. Jobs file = JSON list of `{name, page: rllong|longrun|ab, params: {url params}, minutes, seeds: [1,2], dependsOn: [names]}`; `seeds` expands to jobs `<name>-s<seed>` (params `name`, `seed`, `minutes` are filled in; a `dependsOn` entry is a base or expanded name and waits for all matching jobs). `node tools/queue.mjs start jobs.json` starts a detached runner (`--foreground` to stay attached); `add jobs.json` (append to the live queue through `runs/.queue-inbox`, or to the state file when no runner is alive; several agents share one queue, `start` refuses to discard unfinished jobs without `--replace`), `status [--json]`, `bump <name-prefix>` (stops the runner, moves the matching pending jobs — in the order given — to the head, requeues the job it interrupted and resumes, all in one step), `stop`, `resume [--retry=name,name | --retry-failed]`, `list jobs.json` (dry run: prints expanded jobs and urls). It makes sure `serve.mjs` answers on port 8123 (starts it detached if not, never kills one it did not start), takes `runs/.gpu.lock` (first come first served through ticket files in `runs/.gpu.wait`), then waits until no foreign headless Chrome runs a dev page, launches one headless Chrome per job in the shared profile `runs/chrome-shared` (startup ~1 s; `profileMode: "fresh"` per job restores a throwaway `runs/chrome-q-<job>-<ts>` and deletes it), waits for the log line `done`, an `ERR` line, Chrome exit, a stall (`--stall-seconds`, default 600) or the deadline (minutes + `--grace-seconds`, default 240), retries once on device loss/crash/stall, kills only its own Chrome tree, deletes the profile and records everything in `runs/queue-state.json` (runner output in `runs/queue.log`; a re-run's old log is moved to `runs/.old/`). Example file: `tools/jobs.example.json`.
- `tools/autosize.mjs gen --game=realm|blob [--worlds=512] [--ticks=120000] [--minutes=15] [--seeds=1] [--groups=size,horizon,opt] [--blockgrad=0]` writes a one-factor-at-a-time bracket (`hidden`, `rolloutTicks`, `gamma`, and with `opt` also `lr`/`epochs`/`clip`) plus its own default-parameter baseline arm, for a game whose sizes have never been tuned: architecture sizes are fixed hyperparameters, not learned, so a new game gets one measured. It drops arms whose predicted RL rollout workgroup exceeds 32768 B (realm `hidden` 128 and blob `hidden` 192 both fail pipeline creation; the per-unit slopes are in the file), or marks them `blockGrad 0` with `--blockgrad=0`. `check --game=.. --hidden=.. --rolloutTicks=..` predicts one arm. Judge the round with `tools/report.mjs --at-tick=N --match=^<prefix>-` (the command is printed).
- `tools/gpulock.mjs` is the lock other tools use to cooperate: `node tools/gpulock.mjs status`, `run <owner> <command> [args]` (waits for the lock, heartbeats while the command runs, releases), `clear` (only removes a stale lock). Lock file `runs/.gpu.lock` = `{pid, owner, job, since, heartbeat}`; stale when the pid is gone or the heartbeat is older than 60 s. From code: `import { acquireLock } from './gpulock.mjs'`.
- `tools/evalsuite.mjs [--game=realm|blob|<module path>] [--opponent=<older genome>] [--suites=bots,h2h,selfplay] [--seeds=2|1,2,3] [--worlds=4] [--periods=1] [--top=4] [--jobs=N] [--out=f.json] [--json] [--no-write] <genome>` is the fixed CPU evaluation in Node worker threads: `bots` = the fair protocol (16 learners vs 16 bots, difficulty 100, everyone fresh at each `maxAge` boundary), `h2h` = alternating slots genome vs `--opponent` in 32-slot worlds (sides swap on odd worlds), `selfplay` = 32 slots of the genome (`cfg.learnerSlots = maxLearners`; skipped for games without `maxLearners`). Genomes: dense PPO or sparse evolution (`npc-brain/2`, `/3` with per-node bias, leak and folded input normalisation is read natively, `meta.bias` switches on the evolvable bias node), a file holding a list uses its first `--top`. A bundle (population export) adds the `botsRole` suite (one pure world set per role) and `h2hSingle` (side A = the roles, side B = a single `--opponent`, whose rate is `suites.h2hSingle.summary.opponentRate`). Metrics per suite, mean ± sd across seeds (each seed pools `--worlds` worlds): reward/tick, mean life, action entropy and max single-action share (realm behaviour labels idle/walk/interact/melee/range/mage/craftTool/craftWeapon/buy; other games: dominant signed output), moving share, distance per 1000 ticks, crafts and buys per 1000 ticks, tool/weapon tier at life end and max gear tier, safe-zone share, share of ticks near any player and near a learner ally, death causes per life (mob, boss, animal, player, starve, age), game stats per life (mobKills, greatHarvests, bossKills, pvpKills, ...), plus baseRate and ratio (bots) or opponentRate and ratio (h2h). Writes `<genome>.eval.json` next to the genome (used by `report`) and prints a table and the time. Cost: about 10 s of CPU per 6000-tick world with 16 learners and a 96-hidden dense policy, so the defaults (2 seeds x 4 worlds x 3 suites) take about 2 minutes on 6 workers; subsample with `--worlds`, `--seeds`, `--suites`.
- `tools/report.mjs [--since=72] [--all] [--match=regex] [--limit=60] [--eval] [--set-baseline[=key,key]] [--json] [--no-write]` summarises `runs/*.log` into one markdown table (also written to `runs/REPORT.md`): runs are grouped by name with the `-s<seed>` suffix removed (label `base` dropped, other variant labels appended), columns run, game, seeds, ticks, eval reward x1e3 (mean of the last 3 log windows), bots, ratio, eval life, head-to-head ratio, self-play reward, then evalsuite ratio/head-to-head/self-play from the champion's `.eval.json`, `vs baseline` and notes (`n=1`, `partial`, `running`, `ERR`, `without evalsuite`); a second table shows the evalsuite behaviour metrics; the queue and GPU lock state come first. `--eval` runs a small evalsuite for champions without a fresh result (`--eval-seeds`, `--eval-worlds`). `--set-baseline` stores the current group means in `runs/baseline.json`; later runs flag `REGRESSION` for any directional metric that drops by more than max(2 x sd, 10%) of the baseline.
- Report in the UI: there is no UI for this; open `runs/REPORT.md` (or run `node tools/report.mjs`) to see progress of everything in `runs/`.

## Real-time fidelity
Training is the same fixed-step simulation the shipped game runs, only faster. Brains at runtime are byte-for-byte the training brains, plasticity included (`runtime/npc.js`; multiplayer server `runtime/server.mjs`). See SPEC.md.

## Verification (Run tests button, per game)
world init identical to the JS env; brain forward/learn/structural parity; env lockstep parity word for word (natural and dense scenarios); observation parity (day and night); invariants; statistical equivalence with the CPU backend.

## Layout
`src/core.js` brain, genome, evolution, CPU backend · `src/shader.js` WGSL kernel · `src/engine.js` WebGPU host, tests, benchmark · `src/rl.js` PPO reference math, genome export/import · `src/rlshader.js` PPO WGSL kernels · `src/rlengine.js` `RlBackend` · `src/app.js` UI · `src/games/` game plugins · `runtime/` Node/browser NPC runtime and multiplayer · `SPEC.md` contracts · `GAMES.md` authoring guide · `AGENTS.md` working notes.
